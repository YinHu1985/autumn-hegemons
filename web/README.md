# 春秋风云 · Web

春秋战国背景大战略验证版本。完整设计在根目录 `docs/`，本次实际规则与暂定边界见 [实施记录](../docs/implementation-notes.md)。

## 运行

在本目录执行：

```sh
npm ci
npm run dev
```

先选剧本，再从推荐诸侯或全部国家名录中选国开局；空格暂停／继续，顶部选择 1× 至 16×。地图铺满游戏背景；拖动、滚轮缩放，点击城邑打开左侧省份窗口。内政、科研、人才、军府、战役、百家统一从顶部进入；右侧国势总览提供城邑、军团、科研与营建快捷列表。纪事与系统并列放在顶部辅助区。保存、读取及导入导出统一收在系统菜单，内容工坊也从该菜单进入。每月自动保存。Esc 先关闭当前窗口，无窗口时打开系统菜单。

```sh
npm test
npm run build -- --mode pages
npm run preview -- --mode pages
```

Pages 构建前缀为 `/autumn-hegemons/`。根目录的 GitHub Actions 工作流构建 `web/` 并发布 `web/dist`。仓库更名时修改 `vite.config.ts` 的 `base`。

### GitHub Pages 首次配置与排错

仓库中有工作流不等于已经启用 Pages。首次部署前，在仓库的 [Settings → Pages](https://github.com/YinHu1985/autumn-hegemons/settings/pages) 中，将 **Build and deployment → Source** 设为 **GitHub Actions**。本项目已有工作流，不需要再选择模板。然后进入 [Preview on GitHub Pages](https://github.com/YinHu1985/autumn-hegemons/actions/workflows/pages.yml)，重新运行失败任务或手动运行工作流；后续推送 `main` 会自动发布。操作步骤见 [GitHub 官方说明](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site#publishing-with-a-custom-github-actions-workflow)。

`configure-pages` 的 `Get Pages site failed / Not Found` 表示读取仓库 Pages 站点配置失败，首先检查上述来源是否已设置；若已设置，再确认仓库 Pages 可用性及运行权限。这发生在 Pages API 配置阶段，与浏览器资源路径或 Vite 页面代码无关。工作流已声明 `pages: write`、`id-token: write`。

2026-11-16 排查记录：[失败运行 43813155371](https://github.com/YinHu1985/autumn-hegemons/actions/runs/43813155371) 已成功安装依赖并构建，13:53（上海时间）读取 Pages 配置返回 404；该次日志确认已有 `Pages: write` 权限。排查时远端 Pages API 已返回成功，且 `build_type` 为 `workflow`。据此推断失败时配置尚未启用或尚未生效；目前无需再次调整来源，由维护者重跑工作流验证即可。本次仅做诊断，未推送代码、修改远端设置或重跑发布。

不要只添加 `enablement: true` 来掩盖此错误：[configure-pages v5 的输入说明](https://github.com/actions/configure-pages/blob/v5/action.yml) 明确要求使用 `GITHUB_TOKEN` 以外的令牌才能自动启用站点。当前流程使用默认令牌，由仓库维护者完成一次 Pages 设置即可，无需新增长期凭据。

## 启动加载与素材

启动时先显示全屏加载页，游戏定义与图片、音乐、字库、地图数据并行加载；下载完成后进入选国菜单。进度按实际读取的字节和已完成文件计数，媒体最多同时下载四项，每个请求含响应体最多等待 45 秒。失败可以重试，已下载成功的文件保留；只有非规则资源可以由玩家选择暂缺并继续，游戏定义失败必须重试成功。

`scripts/build-preload.mjs` 扫描 `public/assets/`、`public/map/` 和 `public/music.json`，生成 `public/preload.json`。启动开发服务、正式构建都会自动生成；开发服务运行期间增删素材可另执行 `npm run preload:build`。添加素材不需要修改加载器代码，中文文件名也可用。下载地址与实际显示地址一致，重新访问时由 HTTP 缓存验证更新；音乐在当前会话中复用完整下载的 Blob，避免播放时重新请求整首曲目。进入游戏后另行导入的 Mod 素材仍按需加载。

城景采用保持原尺寸的 WebP，背景音乐采用 MP3，公共资源使用 `/assets/...` 引用并由 Vite 加入 Pages 前缀，避免同一素材同时进入公共目录和带散列的打包产物。压缩参数、来源和体积对照见 [素材审计](../docs/asset-audit.md)。

## 剧本与地图

两个剧本共用 96 城：春秋初期约前 770 年、28 国；战国初期约前 403 年、17 国。推荐诸侯只是快捷入口，名录中的所有国家均可开局。地域和归属采用游戏化近似，难认或难以落实的春秋地名允许用秦汉常见地名代替，详见 [剧本设计](../docs/scenario-design.md)。

`public/content/base/scenarios.json` 列出剧本，`scenario.json` 与 `warring-states.json` 定义各自开局；科技、建筑、军队规则仍共用一个内容包。导入存档或工坊修改的内容另保留“当前内容”开局选项，不会因选择内置剧本而覆盖自定义规则。取消选国不改变当前战局。

编辑城镇位置后运行 `npm run map:build`，构建也会自动执行。`public/map/catalogue.json` 按完整城 ID 与坐标匹配预处理辖区，同城布局共享几何。旧 23 城存档保留原辖区；未预处理的自定义布局先显示底图和城市点，避免误套其他剧本的边界。

## 背景音乐

入口主题采用三国项目的《江山闲赋》，战斗界面循环《旌旗动地》。大地图依次播放《江山闲赋》、A 的三首音乐和 B 的《甲申未至》，播完循环；退出战斗后恢复大地图播放。首次点击或按键后开始播放，系统菜单提供音乐开关、音量和下一首；页面进入后台或打开内容工坊时暂停。音乐偏好只保存在本机，不进入战局存档，也不影响模拟时间。

`public/music.json` 定义曲名、资源路径、主主题、战斗曲与大地图播放顺序，`public/assets/audio/` 保存来自旧项目的六首音乐，总计约 4.71 MiB；其中两首 WAV 转为 MP3，其余四首保持原文件。路径相对于站点根，由构建的 `BASE_URL` 解析，因此支持 GitHub Pages 的 `/autumn-hegemons/` 前缀。换曲或调整顺序修改此 JSON 即可；资源须使用站内相对路径。

## 科研界面

科研窗口参考崇祯工业，左侧为在研科技组和待命科研人才，右上按路线横排三级科技，右下查看工艺、作用、前置与研究安排。顶部仅按科研类别切换，默认打开民生，不设“全部”页签、搜索或成本档筛选。点击锁定科技仍可查看详情；点击前置可跳转。投入与停止操作在左侧科技组卡片中。三块区域独立滚动，大屏增加可见行数，科技牌保持紧凑尺寸，插画只放详情。

## 战争试玩

从军府选择军团和敌方城镇发起进攻。每个防守国仅第一场正常推进，后续最多准备到一半；常规准备九十日。防守方可在战役窗口调整迎战计划或放弃城镇；满进度暂停世界，选择亲自指挥或托管。没有独立围城或援军。

进攻期间（含排队与返程）额外支付远征维护，结束后返程三十日才可再次调度；防守结束立即可调度，但不会补满兵力、士气或已有疲劳。近期参战后主动再进攻会叠疲劳，闲置休整才恢复。军府显示军费拆分、部队疲劳与返程剩余时间；各项数值可在内容工坊的战争规则中调整。

亲自指挥后先部署。开战时双方部队按主动性累积行动条，满条的单个部队获得行动；普通部队 2 AP、骑兵 3 AP，平地移动每格 1 点、林丘 2 点，近战／射击各 1 点。思考与动作播放期间暂停充条，行动结束后短暂匀速充条再轮到下一队；快部队可以在慢部队两次行动间行动多次。训练与士气微调主动性，骑兵默认只有 AP 优势。

战场支持滚轮缩放、按住拖动和方向键平移，棋盘边缘可拖到视口中部避开浮窗；“全图”复位，“当前部队”居中，镜头操作不会下军令。

战场横跨窗口，顶部保留必要信息；军令用浮窗，部队详情与行动顺序窗可分别打开或关闭。顺序列表显示累计条并按剩余条实时排序，另显示按主动性预测的后续行动。移动沿合法路径逐格播放，攻击与计策显示出手、受击和伤亡，AI 同样逐条播放命令。

战场启用战争迷雾：地形始终公开，己方部队共享视野，普通部队默认 4 格、骑兵 5 格；林地和丘陵遮挡视线，其中的敌军默认相邻才会发现。离开视野的敌军重新隐藏，敌方兵力显示为“已发现”，行动顺序及预测只计算已知部队。移动预览不泄露隐蔽敌军，真实行进逐格侦察，突然接敌即停止并只扣实际 AP。AI 同样需要侦察，战报与动画也不公开未观察到的敌方行动。

与敌军贴身后不能移动或射击，仍可近战。操作栏提供坚守、待命、火攻、火矢、疑兵、挑衅与鼓舞；计策显示固定成功率，每队每次行动只能尝试一次，成功失败都消耗行动力。远程依赖实际常备核心；军团将领的统率加成覆盖旗下部队。整场战术冻结战略时间，提交战果计一日。

战场格沿用三国参考项目的纵列错列布局，奇数列下移半格，每格有六个邻向。移动、贴身、远射和计策均按同一六角距离判断；牌面留出地形格边缘，不将兵牌铺满整个格子。

## 内容与 Mod

`public/content/base/manifest.json` 列出内容文件。资源、特产、地形、三级建筑、87 项科技、18 项理念、7 种兵种、事件、战争／战术参数与两套 96 城剧本都由 JSON 定义。网页「内容工坊」提供当前剧本的逐项表单和 JSON 编辑、校验、草稿保存、内容包导入导出与新局试玩。静态网页不会自动写回仓库；导出后将内容更新到源文件提交。

- ID 是稳定引用；名称可改而不改变 ID。普通资源、建筑、科技和兵种无需增加专用程序分支。
- 科技／理念 `effects`、建筑 `modifiers` 使用命名词条；词条定义、中文说明和程序消费位置在 `src/definitions/modifiers.ts`。新规则语义需先实现消费点，再登记词条。
- 建筑 `stage` 表示原料或加工层，`levels` 表示三级升级；`technology` 引用解锁科技。商品投入／产出以每月供给额度解释，只有粮食进入国库累积。
- 科技直系前置用 `prerequisite`，理念无前置；兵种 `requires` 可引用科技或理念，理念必须实行才提供资格。
- `scenario.nations[].baseResources` 提供国家级独立资源。剧本的人力是开局池内存量，初始军队会从中扣除征发人数。
- `warfare.json` 定义准备日数、排队进度上限、返程、远征维护和疲劳。首版初值及字段含义见 [战斗设计](../docs/battle-design.md#数据与模块边界)。
- `tactics.json` 定义基础／骑兵行动力、通用主动性、满条阈值、训练／士气修正、地形移动费用、近战／射击费用、坚守／待机效果及五类计策。`presentation` 控制充条展示速度、逐格移动、攻击和动作间停顿时间，展示时长不改变战果。计策的 ID、名称、AP、射程、固定概率、持续期、伤害、士气和科技／理念 `requires` 引用均可编辑；`effect` 选择程序已有语义。`units[].actionPoints` 可覆盖通用行动力，`units[].initiative` 可覆盖通用主动性；省略时采用通用或基础类别默认值。旧 `movement` 仅供旧包兼容，不参与新战术行动预算。
- `tactics.visibility` 定义迷雾开关、普通／骑兵视野、隐蔽发现距离以及遮蔽／阻挡地形列表；`units[].vision` 可覆盖兵种视野。距离须为 1～100 的整数，当前战场地形支持 `plain`、`forest`、`hill`。旧内容没有视野配置时补入默认值；旧战斗没有双方观测日志时从新事件开始记录，不回放原始全知战报。可在内容工坊调整这些规则。
- 存档写入版本 5，保存内容包及全部世界状态，包括防守队列、返程、疲劳、战术 AP、连续时钟、累计行动条、当前行动者和控制持续期。版本 2／3／4 可迁移读取，旧浏览器存储不删除；旧 `siege.progress` 迁移为进攻方战力词条 `army.offense`，旧内容缺少战争／战术参数时补默认值；旧默认 AP 与费用迁移为 2／3 AP 方案，其他自定义值保留。导入校验失败会显示原因。

## 地图制作

地图菜单与小地图统一放在右下角，不显示颜色图例。地图采用参考 C（三国）的地理底图与离线辖区方案。国家颜色来自剧本，归属来自存档；占领只更新染色和国界，不重算几何。城标、标签与军团旗使用固定屏幕尺寸，浏览器只负责渲染和镜头操作。

```sh
npm run map:build
```

- `public/content/base/scenario.json` 的 `settlements[].map` 是城市坐标，采用 1800 × 1500 地图空间。
- `map-source/frontier.json` 是外围无主定位点，限制稀疏边城的染色范围；它们不参与经济或战争。向外增城时同步调整附近外围点。
- `map-source/land-mask.json` 保存陆地与湖泊矢量，`public/assets/strategic-map.svg` 是独立地理画面。
- `scripts/build-map.mjs` 生成 `public/map/territories.json`，包含城邑辖区、共享边、冻结的城标坐标和可见范围。生成结果可以提交版本管理；预处理不依赖参考项目路径或网络。
- `npm run build`（包括 Pages）会自动预处理。开发过程中修改坐标后运行 `npm run map:build` 并刷新页面；网页内容工坊不重算辖区。已有城市继续显示预生成坐标，新增 ID 先显示城标，完成离线生成后才有辖区。

辖区是游戏化近邻划分，不是考据后的春秋国界；底图已移除三国州名，河道与海岸仍属示意。交通线是相邻辖区的显示辅助，不参与行军寻路。

## 代码职责

| 目录 | 职责 |
| --- | --- |
| `src/definitions` | 类型、数据校验、词条登记与描述 |
| `src/simulation` | 经济、科研、人才、城镇、军团、战役、战术、AI 与统一时钟；无界面依赖 |
| `src/game` | 游戏窗口容器、政令面板和手动战场；使用规则命令／查询 |
| `src/game/hud` | 顶部资源／功能／系统入口及右侧信息列表 |
| `src/game/map` | 地图相机、辖区、城名排布、军团旗、小地图与地图工具；不修改模拟规则 |
| `src/game/loading` | 启动加载状态、进度界面与失败恢复；不参与游戏规则 |
| `scripts` / `map-source` | 离线地图生成与可编辑地图源数据 |
| `src/editor` | 内容草稿、表单、JSON 与试玩 |
| `src/platform` | 浏览器存档、文件导入导出、资源预加载与音乐播放 |
| `tests` | 核心规则与跨系统不变量 |

战术的 `tactical-timeline.ts` 管理连续时钟、主动性与顺序查询；`tactical-turns.ts` 管理单部队结束与逐步自动命令；`tactical-board.ts` 提供六邻寻路，真实移动会再逐格检查接敌；`tactical-field.ts` 提供共享地形和基本单位状态。`tactical-visibility.ts` 统一双方视野，`tactical-events.ts` 分别记录双方实际观察到的战报。展示层 `game/tactical-view.ts` 投影可见部队、兵力、行动预测与动画路段，UI 读取动作记录播放动画，不在 React 中计算伤亡或主动性。

`time.ts` 是日／月结算入口；命令返回新世界，日／月内部系统按确定顺序更新一次副本。不要在面板里扣钱、改人力或自行计算战果。

素材来自参考 A/B/C：A 的人才与理念、B 的冶金插画、C 的地图／城景／UI／地形和字体。历史地名、地理与时代美术仍须校订。当前未实施外交、政策叛乱、贸易；独立围城与援军已取消，城墙提供野战防御条件。
