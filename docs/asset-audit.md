原图约 **55.03 MiB**，只用于素材制作；对应的浏览器图片约 **8.33 MiB**。完整 `public/assets/` 约 **15.74 MiB**，相较此前缩略图版本增加约 4.29 MiB，用于恢复实际细节。原图不在 `web/public`，不会进入 Pages 产物或启动预加载。

### 重新生成

`assets-source/manifest.json` 逐图记录来源项目与相对路径、原图 SHA-256、像素尺寸、发布路径和编码参数。完整说明见 [原图目录](../assets-source/README.md)。在 `web/` 执行：

```sh
npm run images:build
npm run preload:build
```

只在手动重新编码时需要安装 `cwebp`。脚本先验证原图散列与尺寸，再全部生成到临时目录，编码成功后才替换发布文件。`npm run images:build -- --check` 只校验本地原图和发布图，无需编码工具。正常 `dev`、`build` 和 Pages CI 直接使用已生成图片；没有把编码步骤加到部署前置任务。更改原图时应有意更新来源、散列与尺寸；仅调压缩质量时只改清单的编码参数。

## 音乐

选曲、标题、主主题、战斗曲和大地图播放顺序不变。来自参考项目 C 的两首 PCM WAV 转为 MP3，其余四首 MP3 保持原字节。

| 曲目 | 原 WAV 字节 | MP3 字节 | 解码时长 |
| --- | ---: | ---: | ---: |
| 江山闲赋 `strategy-courtyard.mp3` | 4,704,044 | 715,489 | 53.333 秒 |
| 旌旗动地 `battle-banners.mp3` | 3,256,660 | 565,843 | 36.923 秒 |

使用 FFmpeg 的 `libmp3lame -q:a 2`，保持原始 22,050 Hz 双声道，不剪辑、不归一化音量。分别解码到 PCM 后，采样帧数仍是 1,176,000 与 814,154，与原 WAV 一致；MP3 容器显示的时长可能包含约 0.06 秒编码填充。`web/public/music.json` 引用新文件；`web/tests/music-content.test.mjs` 校验六首实际发布音频的散列及场景配置。

可在本机用参考项目 C 原始文件重新编码（工具只在转换素材时使用，运行、构建和部署不依赖它们）：

```sh
ffmpeg -i ../sanguo/src/assets/audio/strategy-courtyard.wav -codec:a libmp3lame -q:a 2 -map_metadata -1 web/public/assets/audio/strategy-courtyard.mp3
```

战斗曲按相同参数替换输入输出文件名即可；图片改用前述本仓库生成脚本。不同工具版本可能产生不同的编码字节；更换发布文件时，应重新确认内容、更新相应音频测试散列，并重新生成预加载清单。

## 避免重复打包

公共素材统一放在 `web/public/assets/`。CSS 使用 `url("/assets/...")`，让 Vite 根据部署 `base` 改写；TSX 中动态路径使用 `import.meta.env.BASE_URL`。不要在 CSS 中再用 `../../public/assets/...`，否则 Vite 会额外生成带散列的导入副本，同时仍复制整个 `public` 目录。

本次修正了六个样式文件中的公共素材引用。Pages 模式构建验证：

- 产出的字体、城景、纸纹和战斗地形 CSS 地址均为 `/autumn-hegemons/assets/...`，且都能对应发布文件。
- 不再额外输出北方城景和 WOFF2 字体的带散列副本，避免再增加约 6.16 MiB 的重复发布体积。
- 音乐与动态城景路径继续遵循相同的部署前缀约定，预加载清单扫描压缩后的发布素材。

新增素材时应先确认尺寸与展示用途，再选择编码格式；不要把原始高体积版本和浏览器版本同时留在公共发布目录。
