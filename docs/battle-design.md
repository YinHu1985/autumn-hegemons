# 战斗与动员设计

更新日期：2026 年 11 月 15 日。用户已确认采用以下攻守不对称规则并授权实施。本文是当前生效的战争设计；旧版战略对峙、额外三十日决战窗口、概率围城和援军方案移至 [战斗设计历史记录](battle-design-history.md)，不再作为实施要求。

## 战役流程

取消独立围城。每次进攻争夺一个城镇，通过准备期后的完整野战决定归属；防守方不能无限拒绝决战。进攻获胜或防守放弃，目标城镇直接转归进攻国；进攻失败或撤军，原归属保持。

只能对关系险恶、且与本国当前领土有道路直接连接的外国城邑发起进攻。按全国调度池判断国土接壤，不要求每支军团驻扎在边城；玩家与 AI 共用校验。目标在大地图点选，返回军府确认军令，详见 [道路与地图交互](map-and-movement.md)。

进攻方发起后立即建立战役、确定本次进攻军团并占用这些部队。准备期暂定九十日，包含本次远征的集结与接敌，不再先走一段敌城行军，再重复等待九十日。友方城镇间的调动仍可保留行军时间。

| 阶段 | 世界与玩家操作 | 部队状态 |
| --- | --- | --- |
| 准备 | 按日推进进度；防守方可放弃目标或调整迎战计划，进攻方可撤军 | 进攻军团被远征占用；防守计划尚未正式占用军团 |
| 决战就绪 | 准备满额后必须处理；玩家参与时暂停世界，选择亲自指挥、托管或放弃 | 锁定本场实际可用守方军团，并从全国人力池动员地方守备一次 |
| 完整决战 | 手动整场世界暂停；自动由内核结算；不支持中途援军 | 实际伤亡、士气等带回原部队，不重新生成满编军队 |
| 结束 | 提交战果一次；正式手动或主动托管计一个战略日 | 攻方延迟回池；守方即时回池，保留伤亡与既有疲劳 |

九十日准备期承担玩家处理内政与组织防守的缓冲。满进度后不再另给三十日窗口，也不静默替玩家跳过决战。AI 对 AI 的战役就绪后自动结算；玩家可选择托管，不被强制要求手动微操。

玩家可以同时看到多场已就绪的进攻战役，依次处理完整决战；没有战术回合之间切换世界的要求。战果提交所计的一日可以使其他准备推进；尚有玩家待决战时，正常走时继续暂停。预约开战、按日／三十日按钮、强制月末集中处理均不引入。

## 按防守国家排队

国家可以同时发起任意场进攻，也可以受到任意场进攻。普通军团／编队软上限和资源约束依然生效，但不存在“一国只能参加一场战争”的全局锁。

每个防守国家单独拥有按发起顺序排列的战役队列：

- 队首正常推进至决战；它可以来自任何敌国。
- 后续进攻可以完成前期集结，进度最多达到准备总量的 50%，随后停在待机状态。
- 队首结束或撤销后，下一场从已有进度继续，不重开完整准备期。
- 不允许因为改编防守阵容、取消后重开或后续进攻加入而重置队首的截止日。重新发起的进攻进入队尾。
- 一个国家自身发起的进攻不占用其防守队列；不同防守国的队首各自推进。

排队是为了限制被动防守的操作压力，表现为尚未取得会战时机。不以“周礼禁止同时交战”作为历史事实。弱敌也会占据队首位置；暂不增加按强弱插队的规则，最低有效进攻兵力是否必要交由实际体验判断。

## 防守编组与无援军

防守方在准备期内可以随时选择放弃或编组迎战。防守名单是计划，不把同一批人复制为多支部队；多个未来防守计划可以引用同一支军团。部队只有真正闲置且可调度时，才能在就绪时进入实际阵容。远征、返程、行军或整训中的军团不能在另一场战役中重复使用。

准备满额时锁定本场防守部队。此后不再修改实际名单或加入晚到部队。进攻名单在发起时就已固定，后发的进攻形成新的战役，不追加为援军。地方守备在本场就绪时从全国人力池按城市规模和驻所条件动员一次；没有野战军的城镇仍可用实际可征的地方守备迎战。若最终没有可作战力量，则按无人迎战处理，不能无限暂停占住队首。

准备期放弃目标不凭空制造伤亡，也不把未发生的决战记作参战。失城对全国人力池存量与上限的影响仍按 [首版结算规则](core-rules.md) 执行。

## 远征维护与回池

进攻军团从发起、排队、准备、作战到返程结束，始终处于远征占用中。除了普通军费，还支付远征附加维护。暂定远征总维护为普通维护的 1.5 倍，附加部分纳入现有军队预算与月底低维护机制。上期实际军费覆盖率同时影响手动与自动战力，低于足额时直接降低战斗效能（当前下限 5%），不能靠将预算归零而无代价维持远征；滑条调整不追溯影响已支付的本期状态。

进攻胜利、失败或撤销都需要返程，暂定三十日；尚未开战就取消也不立即释放部队。返程完成后恢复可调度资格。防守没有远征附加费；普通部队原有维护仍须支付。

防守结束立即回池，包括失败后撤往仍归本国的城市。回池只恢复调度资格，不补满常备、征召、士气或训练，也不清除已有疲劳。灭国则按国家消失规则清理军团和相关未结战役。

围魏救赵由时间承诺体现：玩家比较“当前进攻剩余时间 + 返程时间”和“本土防守剩余准备时间”，决定继续进攻、提前撤退或使用预备军。防守可以连续进行，进攻则长期占用兵力，多军团与预备军因此仍有价值。

## 近期参战与进攻疲劳

单位分别保存最近一次实际战斗的时间与已经累积的进攻疲劳。这两者不是同一个状态。

| 情形 | 结果 |
| --- | --- |
| 最近一次进攻或防守结束不久，再主动发起进攻 | 给参与进攻的单位增加疲劳 |
| 最近一次进攻或防守结束不久，参加防守 | 不新增进攻疲劳 |
| 已经有进攻疲劳，随后参加防守 | 原有疲劳仍影响战力 |
| 部队回池后实际休整 | 逐日恢复已有疲劳 |
| 部队正在进攻准备、排队、返程或其他占用 | 不计有效休整，不自动清除疲劳 |

首版暂定最近九十日内打过仗算“近期”；每次再进攻增加 0.2 疲劳，上限 0.6，战力系数为 `1 − 疲劳`。池中休整每天恢复 `0.2 / 60`，即六十日消除一层。防守不新增这种疲劳，但正常伤亡与士气损失仍存在。

疲劳及参战时间跟随具体部队，不放在可通过换军团清空的容器上。常备转训、调编或重新分组不得抹除已有状态。准备期撤销没有实际战斗，不刷新最近参战日期；若发起时已因近期参战叠加疲劳，撤销也不返还这项状态。

## 城防与目标变化

取消围城后，现有城墙暂作为野战守方阵地条件，和城市地形一起提供防御修正。手动与自动均使用这些修正；地方守备在手动战场中也有实际部队。城墙未来是否额外影响准备时间或部署，再做平衡，不重新引入独立围城进度。

目标先被第三国占领，原进攻失效并进入返程，不自动把战争目标改为新主人。灭国时清理该国军团、将领占用和涉及该国的未结战役，不能遗留永远占位的防守队首。

## 数据与模块边界

战争参数放在 `web/public/content/base/warfare.json`，由内容包清单加载并经统一定义校验进入模拟。定义编辑器、存档和模拟使用同一套规则；UI 只展示队列、状态和命令结果，不自行计算战果或扣费。

手动战术的行动力、移动和攻击费用、计策定义独立放在 `web/public/content/base/tactics.json`，不和战略准备／返程参数混放。兵种仍由 `units.json` 定义，基础兵种类别由程序识别；名称、属性、射程和解锁引用可以在文本中调整。战术规则细节见下节。

暂定参数表：

| JSON 字段 | 初值 | 含义 |
| --- | --- | --- |
| `preparationDays` | 90 | 一场进攻的完整准备日数 |
| `queuedProgressCap` | 0.5 | 非队首可完成的最大准备比例 |
| `returnDays` | 30 | 进攻结束或取消后的返程日数 |
| `expeditionUpkeepMultiplier` | 1.5 | 远征期间相对普通维护的总倍数 |
| `recentCombatDays` | 90 | 再进攻会叠疲劳的近期参战范围 |
| `offensiveFatiguePerAttack` | 0.2 | 每次符合条件的进攻新增疲劳 |
| `maximumOffensiveFatigue` | 0.6 | 疲劳上限 |
| `fatigueRecoveryDays` | 60 | 池中休整清除一层疲劳所需日数 |

以上数字只用于首轮试玩，不是已完成平衡的最终值。攻守不对称、无围城、按防守国排队及疲劳触发方式是已确认规则。

## 手动战术：行动力、牵制与计策

参考 C 的战斗交互改造：每支部队是一枚放在地形格上的兵牌，格子仍显示地形与可达范围；兵牌显示人数、士气、剩余行动力和控制状态。编组仍是一支军团由一名将领统领，将领加成覆盖所属军团的部队，不给每枚兵牌再配一个将领。

战场沿用 C 的纵列错列布局（odd-q）：奇数列下移半格，每个内部地块有六个相邻地块。移动、贴身牵制、近战、远射、计策与 AI 使用同一六邻拓扑和六角距离，不使用方阵的曼哈顿距离。存档仍保存整数列／行坐标，不因为展示错列而重写部队位置。

部署期可以自由调整己方阵列，不扣行动力。开战后双方所有部队各自积累行动条，首先满条的部队获得一次行动，花费自己的 AP；该部队结束后再继续累积。没有“先操作完整个己方，再操作整个敌方”的阵营回合。整场战术期间世界冻结，战术时钟与战略日期分开；提交正式战果才计一个战略日。

### 主动性与连续行动条

- 首版通用主动性为 100，行动条阈值为 100。训练与士气分别以 50 为基准，在各自 0～100 范围内最多造成 ±10% 修正；兵种的 `initiative` 可选字段可以覆盖通用主动性。骑兵默认优势是 3 AP，不自动获得额外主动性。
- 空档期间按 `主动性 × 战术时钟增量` 为所有存活部队充条，精确推进到首个满条者，不越过它。玩家思考、当前部队连续下令或动作动画播放时暂停充条。多队同时满条先按主动性、再按稳定部队 ID 裁决，处理下一队不额外经过时间。
- 每次只激活一支部队，恢复它的 AP、施策机会并清除它上次的坚守姿态；其他部队不刷新。行动结束时该队扣除一个完整行动条，其余部队保留进度。快部队可以在慢部队两次行动之间多次行动，不用固定轮次压平差异。
- 行动顺序窗显示已知部队的当前条、主动性与预计等待时间，列表始终按“距离下一次行动还差多少条”排序，随着充条实时上移、下移。未发现敌军不进入列表。条剩余量与预计等待时间是两个不同概念：主动性不同，条落后的部队仍可能先行动。
- 另列未来若干次预计行动，仅按当前可见部队的主动性推算，允许同一部队多次出现；这是已知情报且士气和训练不再改变时的预测，发现敌军、战损和鼓舞等发生后重新计算。真实调度仍计算双方所有存活部队。

### 战场布局与动画

战场横跨窗口，上方只保留战役、双方兵力和当前行动等必要信息。行动选项放在浮窗；部队详情、战报与行动顺序是可以单独打开或关闭的浮窗，不固定占据战场侧栏。保持原有错列格，不采用参考图片中的菱形格。

战斗视野沿用主地图操作：滚轮以指针为中心缩放，按住拖动或方向键平移。棋盘四周允许留出纸面空白，四条边均可拖至视口中央，便于避开浮窗；镜头范围有限，不能把整张地图甩出视口。提供“全图”复位和“当前部队”居中。棋盘、兵牌与动作动画一起移动、缩放，军令及其他浮窗保持屏幕位置。拖动手势不触发格子军令；暂停和动作播放期间仍可查看地图。

移动逐格沿模拟给出的合法路径播放，不以起终点直线穿过部队或敌军牵制区。近战、远射与计策分开展示出手、目标受击和伤亡；动作播放完成再推进下一条命令，AI 也逐命令执行。逻辑只结算一次，动画读取动作记录，不重复计算命中或伤亡。界面的匀速充条和短暂停顿让玩家看清下一行动者，展示速度与模拟中的主动性彼此独立。

### 行动力与近身牵制

- 首版普通部队每次行动 2 点行动力，骑兵 3 点；兵种 `actionPoints` 可覆盖默认值。
- 平地每格 1 点，林地和丘陵每格 2 点；可向六个邻格移动，不能穿过任何存活部队。寻路预览和实际命令使用同一费用。
- 近战和普通射击各消耗 1 点。移动不直接结束行动，可以先走再打，也可以在行动力足够时继续攻击。
- 与存活敌军在六个方向中任意一格相邻即受到贴身牵制，不能主动移动。部队可以走到敌军身边，但不能在同次路径中继续穿过其控制区；接敌后仍可近战。
- 待命结束该队本次行动并恢复 2 点士气，上限 100；坚守结束该队行动并将防御乘以 1.35，持续至其下次行动开始。这两个初值分别由 `waitMoraleRecovery` 与 `guardDefenseMultiplier` 配置。

上述数值是试玩初值，可在 `tactics.json` 中调节。军团战略调动速度与战术行动力分开计算，不能因战术改版改变既有远征准备和返程规则。

### 近战与远程

普通攻击区分相邻近战与显式射击。近战可能受到存活目标的反击；射击不触发近战反击。专业远程部队被敌军贴身后不能继续射击，可以用较弱近战能力作战。

远射要求兵种具备远程射程且仍有常备核心。弩兵和器械部队的射击输出按实际常备人员计算，征召护卫不会因归属远程模板就变成射手。常备全损后保留征召部队，其远射能力消失，仍可近战。地形、训练、士气、军团统率、军备与预算效率、已有疲劳仍参与战力计算。

### 计策与控制状态

首版提供火攻、火矢、疑兵、挑衅、鼓舞。每支部队每次行动至多尝试一项计策，消耗配置的行动力；成功率暂为定义中的固定值。成功或失败都消耗本次行动机会与行动力，非法目标、未解锁或行动力不足则不扣费。本版不另设随军金钱池，不从国家财政即时扣除施策费用。

| 效果 | 当前含义 |
| --- | --- |
| 火攻 | 对有效敌军尝试造成额外伤亡与士气损失 |
| 火矢 | 需要远射能力，先完成射击，再独立判定是否点燃；引燃失败仍有正常射击 |
| 疑兵 | 使目标跳过随后规定次数的完整行动 |
| 挑衅 | 在目标随后行动时强制其追击施术部队并尝试近战，遵守地形、占位和贴身规则 |
| 鼓舞 | 对友军或自身恢复士气，不能作用于敌军 |

当前试玩参数如下，均为 `strategies` 数组中的可编辑值，不表示已经完成平衡：

| 计策 | AP | 射程 | 固定成功率 | 附加效果 |
| --- | --- | --- | --- | --- |
| 火攻 | 2 | 2 | 60% | 火伤系数 0.12、士气 −10 |
| 火矢 | 2 | 至多 3，且不超过兵种射程 | 35% 引燃 | 普通射击后追加火伤系数 0.08、士气 −8 |
| 疑兵 | 2 | 3 | 50% | 阻止 1 次完整行动 |
| 挑衅 | 1 | 3 | 60% | 强制追击 1 次完整行动 |
| 鼓舞 | 1 | 2 | 100% | 士气 +12，上限 100 |

控制持续时间按被影响部队完成的行动计算，不能通过重复查询或施术方自身操作缩短。已有同类控制不能重复刷新；挑衅源失效时取消追击。AI 和玩家调用相同合法性、AP、施策次数和控制规则。

每个计策的 `requires` 可以引用科技或理念：科技研究完成即解锁；理念需已经实行。当前先提供可玩的基础计策，引用入口可以在内容工坊中配置，不把固定成功率和解锁条件藏在界面里。增加全新效果语义仍需要在程序注册处理逻辑；仅改名称、费用、射程、概率、持续时间及引用不需要改程序。

### 战争迷雾与共享视野

参考 C 的战场情报规则：地形与格位始终公开，敌军只有处于己方任一存活且未溃退部队的视野内才会显示。部队共享视野，部署阶段同样生效。只记录当前可见范围，敌军离开视野后重新隐藏，不保留随敌军移动的记忆兵牌；战斗结束后开放战场供查看结果。

普通部队默认视野 4 格、骑兵 5 格，距离采用同一错列六角距离。林地和丘陵遮挡穿过它们的视线，藏身其中的敌军默认只有相邻时才能发现；相邻格总能观察。视线按六角网格逐格检验，沿地块边界的射线检查两侧，避免从林丘缝隙穿透。它控制目标发现，不额外增加一套射击弹道遮挡规则：侦察到的目标可以由共享视野中的远程部队按射程攻击。

未发现敌军不能被选中攻击或施计，也不能通过移动预览泄露占位或控制区。预览只考虑已知敌军；真正移动时逐格侦察，发现前路被占或接敌时停止，按实际走过的地块扣除 AP。AI 使用同一视野查询，未发现敌军时向对方公开部署方向搜索；受挑衅的部队也不能追踪不可见施术者的位置。

顶部敌方人数表示当前已发现兵力。部队详情、定位、行动条和预测只展示已知敌军；动画只播放可见路段，不凭移动终点提前揭示视野。隐蔽射手造成的己方伤亡仍有反馈，但不显示指向未知来源的箭迹。战报在事件发生时按双方当时视野分别记录，后续发现敌军不补发之前的隐蔽行动。当前只接受现行格式存档。

数据配置位于 `tactics.json.visibility`，包括 `enabled`、`baseRange`、`cavalryRange`、`concealmentRange`、`concealmentTerrains` 和 `blockingTerrains`；`units[].vision` 可覆盖单个兵种的默认视野。距离为 1～100 的整数，当前战场地形列表支持 `plain`、`forest`、`hill`。新内容包默认开启迷雾；旧内容缺少该对象时补入同样默认值。伏兵专属状态、谨慎移动和战略大地图迷雾尚未纳入本轮规则。

## 常备核心与征召补充

### 已确认的兵制结构

常备核心决定一支部队的专业兵种与主要输出，征召人员提供兵力规模并承担主要伤亡。两类人员在部队内部共同存在，同时保留没有常备核心的纯征召部队；多支部队再组成由一名将领指挥的军团。

每支部队保持一个主兵种模板、独立身份和战损记录。征召补充挂在具体部队下，不作为全军团共用的一条血池。界面显示实际总人数，详情分别显示常备与征召人数，使玩家能看出专业核心与总兵力的区别。

例如一支弩兵部队由 200 名常备弩兵和 1,800 名征召人员组成，实际总兵力为 2,000，弩射能力主要来自 200 名常备。征召人员提供护卫、辅助战列、基础近战与承伤，不会因加入弩兵部队就全部变成弩手。示例人数不是编制定值。

### 兵种能力

科技与理念解锁可用兵种；招募相应常备核心后，该部队才获得对应专业能力。将领不承担兵种解锁，常备核心也不是额外的一套人物或副将系统。

| 部队类型 | 常备核心的作用 | 征召人员的作用 |
| --- | --- | --- |
| 纯征召步兵 | 可以没有常备核心 | 基础步兵作战、人数与承伤 |
| 弩兵 | 弩射输出与专业训练 | 护卫、辅助战列、基础近战与主要承伤 |
| 重步兵 | 重装作战、突破与抗线能力 | 扩展战线、补充人数与主要承伤 |
| 战车 | 战车作战与冲击能力 | 随车步卒、协同与主要承伤 |
| 骑兵 | 骑兵作战与机动能力 | 特殊编制，可以不依赖步行征召人员 |

纯征召部队当前限定为基础步兵。未来是否增加基础弓兵能力再决定，不默认可以组建纯征召弩兵、重步兵、战车或骑兵。

### 输出与伤亡

专业输出主要按常备数量、兵种能力、训练装备及部队状态计算。征召提供基础作战贡献，但不能按总人数直接套用专业兵种输出。

正常交战主要损失征召，常备受到一定保护。征召减少时，专业输出不必同比下降；随着征召不足，阵线维持和保护能力下降，常备受损风险升高，严重时也会影响输出发挥。溃败、包围和追击可以进一步伤害常备核心。

常备不是绝对免伤，具体伤亡分配公式和保护程度待平衡。玩家需要权衡继续作战与保存昂贵核心：部队可能仍有较强输出，但继续战斗将承担更大的常备损失。

征召人员承担补足人数与主要承伤的作用，常备兵则同时承担专业兵种和主要输出，不能只把常备理解为提高所有士兵质量的组织加成。

### 常备比例与发展

科技和军制逐步提高允许的常备比例或编制上限。提高常备数量，以更高的长期财政、训练和装备成本换取更强战斗力；具体上限可以按兵种分别设置，不要求所有兵种采用同一比例。

例如同样 3,000 人编制，早期可能为 300 常备加 2,700 征召，后期提高到 900 常备加 2,100 征召。总人数相近，专业输出提高，维护与核心损失的代价也上升。比例仅用于解释机制，不是已确定数值。

玩家可以维持较低常备比例以节省长期成本。征召集结较快但需要整训，常备补充更慢且长期投入更高；补满总人数不代表已经补回专业核心或恢复原有战斗力。

### 起步保障与征召成本

一地国不需要先建立完整资源和军工链。城镇规模提供基础财政与人力，配合支付主财政粮食的征召起步。原常备基础配额已归入通用国家基础资源；国家可独立提供任意配置资源，包括直接支持起步常备的军备额度，首都仍只作标记。详见 [国家基础资源](core-rules.md#国家基础资源)。

纯征召部队和常备部队中的征召补充，都只支付主财政粮食并占用可征召人力。临时装备和衣粮抽象进费用，不逐项检查铜、木材、布匹或专业军备额度，也不另加随军口粮门槛。粮食财政身份与城镇规模规则见 [城镇设计](settlement-design.md)。

常备和专业兵种通过产业或起步保障取得共享军备额度，各兵种需求不同。财政维护不足降低士气等状态，军备不足按缺额惩罚；都保留部队。费用、需求量和集结时间待调，完整关系见 [特产与生产设计](production-design.md)。

### 骑兵与混编机动

骑兵按后期强力、昂贵且具有独立机动价值的兵种设计，可以采用高比例乃至全常备编制，不要求步行征召兵充当承伤层。其能力由军马、装备、维护和训练成本支撑；具体常备比例与数值待定。

纯骑兵军团保留较高行军速度，加入步兵等部队后按混编后的机动能力行动。不能让骑兵携带大量步行征召人员，却仍无代价地维持纯骑兵速度。

战车搭配征召步卒时按车步协同理解，随车步卒不会直接获得战车的移动能力。当前战术按普通部队 2 AP、骑兵 3 AP 起步，并允许在兵种中覆盖；军团战略速度与混编的具体公式仍待细化。

## 全国人力与恢复

城镇规模和治理效率贡献全国人力上限与增长，人口暂时抽象。全国只保留一份可用人力池，军团征募、补员和地方守备共同消耗；在役不占池子上限，征发从池移到部队，复员将实际人员返池，超出上限的返还量抹除。

失城按上限缩减比例扣除池内存量，例如上限 100 变 90、存量 50 变 45。同次失城只缩减一份全国储备，已经在役的部队不因此同比消失；战死人员不返池。该规则取代此前按省记录来源和三层人口表，详细公式见 [全国人力池](core-rules.md#全国人力池)。

常备、征召与地方守备均从同一全国池征发；地方守备在决战就绪时动员一次，存活者战后返还同池且受当前上限裁切。每月恢复上限的 1.5%；得城增加容量，不凭空填满储备。征召对生产的额外影响及伤病是否单列仍待定。

## 国家关系与软限制

国家开局关系 +20，只有关系险恶时可对相邻城邑出兵。占领即转移领土，失去全部城镇即灭国；首都只作标记。外交数值与使者任务见 [外交设计](diplomacy-design.md)。

军团与编队等组织能力采用软上限，允许超额但给予明显惩罚；资源不足同样按缺额惩罚。目标是常规情况下惩罚略超过新增单位的优势，同时允许极端情形超额。具体处罚范围与曲线后定。

理念变化导致已有兵种不可用时，按该兵种上限为零处理，保留部队但战斗力约为零。零上限采用专门处理，不套用普通比例除法；人力复员裁切仍按其明确规则执行。

## 尚待平衡与扩展

- 准备期、排队上限、返程时间、远征维护和疲劳的具体数值。
- 城墙、地形和地方守备的防御强度；是否需要最低有效进攻规模。
- AI 在撤军回防、保留预备军、进攻目标与部队休整之间的取舍。
- 各兵种常备与征召编制、常备比例上限、专业输出与伤亡分配公式。
- 骑兵的具体比例、成本、战术移动与友方调动速度；纯征召是否增加基础弓兵。
- 地方动员量与恢复强度、征召对生产的额外影响、是否单列伤病。

这些事项不改变当前“准备 → 完整野战 → 攻方返程／守方回池”的基本流程。援军、独立围城和外交不在本轮实现范围。
