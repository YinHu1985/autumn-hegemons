# 首版结算与运行规则

更新日期：2026 年 11 月 15 日。记录用户确认的首版规则，补充 [城镇设计](settlement-design.md)、[生产设计](production-design.md) 和 [战斗设计](battle-design.md)。战争流程已按最新攻守队列方案更新，实际实现与暂定数值见 [实施记录](implementation-notes.md)。

## 预算与低维护

各大类分别设置足额维护的支付比例，例如军队 80%、科研 100%，不是各类瓜分一个合计 100% 的预算饼。具体分类后定。玩家和 AI 均使用这一预算机制。

所有月底维护项目都要定义低投入效果。军队维护不足降低士气等状态，建筑维护不足降低产量，科研等系统也必须根据实际维护而非计划投入运行。低维护不直接删除对象；具体曲线、作用范围和恢复速度以后调。

记某类足额需求为 `C_i`、滑条比例为 `r_i`，则计划支付 `P_i = C_i × r_i`。设月底可用存粮为 `S`、本月结算收入为 `I`、总计划支付 `P = ΣP_i`：

- 若 `P = 0`，所有类别实际支付均为零，不计算除法。
- 若 `P > 0`，统一缩放系数为 `k = min(1, (S + I) / P)`。
- 各类实际支付 `A_i = P_i × k`，国库结余为 `S + I − ΣA_i`。
- 有足额需求的类别，其实际维护比例为 `A_i / C_i`，不能只使用 `k` 而忽略玩家主动降低的滑条比例。

上述是用户规则的数学表达，余额与收入按非负财政入账处理，不因维护不足产生未定义的负余额或债务。一次性建设、征募、刷新人才的付款时点与取消返还另定，不自动混入月底维护的比例分摊。

## 月底收入与下月状态

用户已确认采用一周期滞后：本月收入按已经确定的运行状态结算；月底实际支付的维护比例决定下月运行状态。不能再用下月的新比例反向降低已经结清的本月收入。

按此顺序处理：本月运行与收入形成 → 月底收入入账 → 计算各类足额需求和计划支付 → 财政不足时同比缩减 → 扣除实付 → 更新下月维护状态。

生产、财政和科研的实现须遵守同一周期口径：本月效果按既有维护状态计算，不因月底实付变化而追溯重算；下月必须使用新的实际维护状态。月内新建、升级、扩军以及开局尚无上一期支付记录时，使用什么初始运行状态、是否需要补付，是剩余实施边界；不得默认新增对象免费获得完整维护。

## 军工与兵种资源

军工作坊提供二级商品额度，例如皮革转皮甲。不同兵种按模板配置占用不同种类和数量的军备额度；不再采用每种作坊直接增加对应兵种上限的分支。

现役军备需求超过供给时，根据缺额给予明显惩罚，仍保留部队。财政维护不足、商品供给不足和编制超额分别解释原因；它们怎样叠加、如何分配短缺以及驻扎／出征／补员是否采用不同需求仍待定。

## 国家基础资源

用户已确认：基础配额就是国家基础资源。国家本身可以独立于其他经济来源，直接提供任意配置资源，用于开局启动（bootstrap）和调配平衡，俗称国家级全局“火星”资源。这是通用资源来源，不限于军备，也不要求对应城镇、特产、作坊、原料或首都。

国家定义中应能按稳定资源 ID 配置基础贡献；可供给的资源不能写死为当前几种货物。粮食贡献作为经常性财政收入，纳入月底可用收入 `I`；铜铁及二级军备贡献作为持续供给额度，与产业实际供给合并后参与分配。普通商品不因此变成每月累积的库存；开局一次性存粮与持续基础收入是不同数据。

最终收入／供给必须容纳“国家基础贡献 + 其他来源的实际贡献”。国家基础部分不自动受到地方治理、建筑维护或原料断供的缩减；国家级加成是否适用由明确的计算作用域决定，具体数值后调。账目应能展示国家基础来源，界面与 AI 使用包含该来源的汇总结果。

原少量常备保障通过配置国家基础军备资源实现，作为已采用的国家基础供给配置。配置任意资源仍须遵守其记账语义；若涉及人力，要区分池上限、恢复和实际入池，不能绕开既定人力规则。具体字段与编辑入口见 [架构与数据驱动设计](architecture-design.md)。

## 全国人力池

人力采用唯一的全国池，军团征募、补员与地方守备共用，在役人员不占用池子上限。征发是将人力从池子移到部队；复员是将实际存活人员从部队移回池子，超过上限的返还部分抹除。本文将用户的“复原”统一记为“复员”。

不再设置防御专用储备。地方守备在决战就绪时从全国池动员一次，战后幸存者返还同一池并按当前上限裁切；死亡人员不返还。每月恢复量为全国人力上限的 1.5%，只补充空缺，不超过上限。

失去城镇时，扣除它贡献的人力上限，同时按上限缩减比例扣除当前池内存量。若旧上限 `M_old > 0`，新上限为 `M_new`，则新存量 `H_new = H_old × M_new / M_old`。例如上限 100 降到 90，存量 50 变为 45。零上限的边界显式处理，不能除以零。同一次失城只对这份全国存量缩减一次。

该比例损失作用于池内存量，不反向删除已经在役的部队。战斗死亡的人不会在复员时返还。这里上限约束可用储备，不限制国家总在役人数，取代此前按省追踪与在役占容量的候选。

得城、扩城与治理恢复只增加相应容量，空缺靠每月恢复填充。因治理或政策变化而降低上限的细则仍可后续调整。

## 首版战争与国家

国家关系开局为 +20，按年度向中心值回归；仅关系险恶时可以对道路接壤的外国城邑发起进攻，具体见 [外交设计](diplomacy-design.md)。成功占领即转移领土归属，失去全部城镇即灭国；当前不引入宣战、议和、割地谈判或独立的长期军事占领状态。

首都暂时只是标记，不提供特殊能力。小国起步配额已经归入通用国家基础资源，独立于首都；迁都或占领一座首都不会因此重复获得国家基础来源。

玩家代表国家本身。君主以后可以作为国家级 buff 加入，当前不需要君主寿命、继承或个人死亡导致游戏结束的系统。灭国后的残余军队和在途命令清理、统一后的提示或继续沙盒可在实现相关流程时确定。

## 日推进与建设

世界按日推进，经济月底结算。友方调动、进攻准备、返程与池中休整逐日计算。每个防守国家仅队首正常推进，后续进攻最多完成一半准备；满进度进入必须处理的完整野战。当前不支持援军，进攻名单发起时固定、防守名单决战就绪时锁定。玩家待决战及手动战术暂停世界，正式手动或主动托管的战果提交计一个战略日。

完整手动决战期间世界暂停、整场按一个战略日计的共识不变。该战略日具体在开战前还是战果提交后推进，以及它与同日其他命令的先后，仍需固定，但不重新讨论整个按日／月底分工。

每个城镇同时只允许一项建筑施工，不同城镇可以并行。建筑耗时完成；规模提供个位数数量级的建筑容量，小城可以只有一个建筑位。升级不增加容量占用。扩城是否占用同一施工队列、哪些建筑占位、取消与易手后的工程处理仍待定。

## 人才与事件

人才招募池随机出现新人，参考已有项目；每隔若干年刷新或允许消耗资源手动刷新是当前方向，具体周期、费用、保留条目及是否两种方式并存待定。

人才从被招募起计时，满 20 年后每次过月随机判定死亡退场，不是恰好第 20 年必定离开。概率后定；不据此要求实现完整出生年龄模型。人物退出后岗位、研究组与军团的接续方式仍需定义。

事件长期不处理，达到期限后默认选择第一个选项。期限和选项失效时的处理以后定；建议第一项设计为到期仍能执行的保底项，避免默认结算卡住。该建议尚未确定具体内容格式。

政策和叛乱明确留到以后，不列为当前原型前置任务。

## 软上限与失去资格

组织与能力上限采用软限制，允许极端情况下超额，但给予明显惩罚。平衡目标是超过上限造成的相关代价略大于多出一个单位带来的常规优势，防止稳定套利；具体范围、曲线及叠加方式后定。

军备不足同样按缺额惩罚。理念变化使已有兵种不可用时，按该兵种上限为零处理：部队可以保留，但战斗力约等于零。零上限必须是明确分支，不能套用会除以零的普通超额比例。未解锁兵种是否允许新招募不能由“可以保留旧部队”自动推出。

人力复员超额裁切、失城同比扣池是用户另外明确的规则，仍优先执行，不改成可以无限存人的软池。建筑位、单组科研投入等具体上限如何归入软限制，以及每种惩罚影响哪些对象，需要逐项列明；不能自动把所有技术性最大值都改成可突破。
