# 完整计划缺口审查

更新日期：2026 年 11 月 15 日。已纳入用户对财政、人力、战争、建设、人才和软上限的回答，以及预算滑条、每城施工、维护周期的三项确认。完整规则见 [首版结算与运行规则](core-rules.md)；战争部分已按 [最新战斗规则](battle-design.md) 替换旧围城和决战窗口，实际实现见实施记录。

这些回答足够支撑首版详细设计。主要系统已有明确方向，不需要把外交、人口、政策或叛乱重新展开才能继续。下列剩余项在实现对应模块前补齐即可，具体数值可以后调。

## 已确定，不再作为开放选择

| 系统 | 当前规则 |
| --- | --- |
| 平台与内容 | 继续 Web；JSON 定义内容，程序实现语义，游戏与定义编辑器共用格式和校验 |
| 城镇与财政 | 地形、规模、治理和专门建筑；规模提供基础粮食收入、人力和建筑容量，人口抽象 |
| 粮食与商品 | 粮食可积累，普通商品是持续额度；粮食和鱼共用仓库，农业路线合并后科技仍为 87 项 |
| 维护预算 | 各类独立设置足额维护比例；总计划支出超过存粮加收入时，各类按同一系数缩减 |
| 维护周期 | 本月按既有运行状态结算；月底实付决定下月状态，低维护影响军队、建筑、科研等系统 |
| 军备接口 | 军工作坊提供二级军备商品额度，各兵种按模板占用，短缺按缺额惩罚 |
| 国家基础资源 | 国家可独立于其他经济提供任意配置资源，用于开局启动和平衡；粮食计收入、商品计持续额度，不绑定首都或产业 |
| 人力 | 唯一全国人力池供军团征募、补员及地方守备共用；在役不占上限，月恢复 1.5%，复员与守备幸存者回同池并裁切超额；失城按上限缩减比例扣存量一次 |
| 战争与国家 | 初始关系 +20，仅险恶关系允许进攻相邻城邑；占领即领土转移，全失城即灭国；首都只作标记，玩家代表国家 |
| 时间 | 日推进、月底经济结算；当前无援军，待决战与手动完整决战暂停，战果计一个战略日 |
| 战役 | 准备期后强制野战；每防守国队首推进，其余最多半程；进攻维护／返程／疲劳，防守即时回池 |
| 兵制 | 常备决定兵种与主要输出，征召提供规模并承担主要损耗；征召仅需财政粮食与人力 |
| 建设 | 每城同时一项建筑施工、城间并行；容量个位数，升级不增加占位 |
| 人才 | 随机招募池；招募满 20 年后每月随机死亡退场，刷新周期及付费方式待配 |
| 事件 | 到期未处理默认第一项 |
| 软限制 | 能力超限和军备短缺给予明显惩罚，保留对象；已有兵种因理念失去资格时战力近零，人力裁切仍执行 |
| 理念 | 三个成本档位的独立研究项目，无研究前置；解锁与槽位实行分开 |
| 外交 | 全国家对称关系、年度向 +20 回归；使者占用执行赠礼或谴责任务，进度完成时改变关系 |
| 明确延后 | 宣战／议和等进一步外交、政策、叛乱；君主可在以后作为国家级加成加入 |

## 一、跨系统剩余边界

| 事项 | 需要补齐的部分 | 当前建议或约束 |
| --- | --- | --- |
| 月内新增与一次性费用 | 新建筑、新部队、新研究组以及开局对象的初始维护状态；一次性费用的扣款时点与取消退款 | 不能让新增对象无意取得免费足额维护；不因周期规则冻结所有月内操作 |
| 商品额度分配 | 全国或局部供给、争用原料的分配方式、配方环路、缺额如何逐层传递 | 与财政按比例缩减是两件事；不能由建筑遍历顺序决定结果 |
| 人力上限其他变化 | 治理和政策降低上限时的处理细则 | 得城、扩城和治理恢复只增加容量，靠月恢复填充；地方守备决战就绪时动员，失城只对全国池缩减一次 |
| 建设队列与容量 | 扩城是否共用队列、通用与特产建筑是否占位、同类实例、取消／易手后的工程 | 每城一项施工和升级不增占位无需重新讨论 |
| 软限制适用清单 | 每种超限的受罚对象、零上限分支、惩罚叠加；建筑位与单组科研规模如何归类 | 人力池按已确定的裁切规则；保留失去资格部队不自动等于允许招募未解锁兵种 |
| 日内顺序 | 决战占用一天的落点、同日科技完成／事件／命令／战果的顺序 | 当前无援军；保留准备期内合理安排顺序的收益 |

## 二、实现对应模块时补齐的操作出口

| 模块 | 剩余事项 |
| --- | --- |
| 地图与行军 | 城镇与省份映射、邻接路线、遭遇位置、跨水域和撤退目的地；首版不必做海战 |
| 战役与战术 | 准备与排队数值、返程与疲劳强度、城防效果、AI回防与预备军策略、战术行动与自动求解 |
| 部队 | 拆并、换型、征召附入、常备补员、训练和恢复的合法状态，以及复员出口 |
| 科研 | 席位类别、启发分组、专业标签；启发去重与封顶、世界传播、停研换人；低维护效率曲线 |
| 理念 | 槽位类别与解锁、兼容与切换、生效时点；理念不设前置的规则不变 |
| 人才 | 招募／维护／刷新费用，定期与手动刷新的组合，退场后的职位与课题接续 |
| 事件 | 默认第一项失去目标或支付条件时如何执行；建议提供始终可执行的保底结果，尚未确认格式 |
| 国家结束 | 灭国后的残余军队和在途命令清理，统一后的提示或继续沙盒 |
| AI | 基于共同预算选择投入，安排建设科研，选目标、出征、回防、撤退；不要求首版议和策略 |

AI 读取资源用途、配方关系、兵种大类和内核收益查询。同机制的新内容应能被已有策略使用；新增机制仍需对应评估逻辑，不要求自动理解任意词条。

## 三、可延后与内容制作前再决定的事项

科技与理念的具体效果、国家基础资源配置数量、生产配方数量、战役准备和疲劳参数、兵种攻防、人才能力数值、治理恢复幅度、事件文案和美术排版，都可在对应模块验证时调整。

贸易作坊仍只是候选，不要求先建全球市场；不新增完整人口、粮食运输、普通商品库存或独立稳定度。治理恢复仍属于首版城镇规则，政策和叛乱系统本身明确延后。

开局年代、地图范围与首个验证场景要在制作正式内容前选定；此前约四国二十省仍只是验证建议，不代表正式地图规模。

## 四、后续验证落点

现有定义层、模拟内核、界面、编辑器和平台适配的分工足够。后续重点检查：

- 财政存量、人力池与商品额度分别记账；粮食能结余，铜铁不能凭空积存。
- 国家基础来源可独立供给任意已定义资源，无需城镇或作坊；最终收入／供给、来源明细与 AI 计算均包含该贡献，不把额度误记为逐月库存。
- 多类维护同比缩减时仍保留各自滑条差异，本月结果不被月底的新维护比例追溯改写。
- 新增、撤销或失去对象不会重复收费或无意取得完整免费维护。
- 征发、死亡、复员、失城与恢复守住两人力池账目，部队不因池上限下降被直接删除。
- 占领、治理恢复、供给短缺和灭国能完整回写世界；超限和失去资格都有明确惩罚。
- 岗位空缺、事件目标失效、战败与读档均有出口，跨月和战果提交不重复扣费或发奖。
- AI 与玩家使用同一套状态和成本规则，决战择时仍保留已约定的操作空间。

这些是后续验收方向。实施进度与测试结果以 [实施记录](implementation-notes.md) 为准。
