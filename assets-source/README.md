# 原始美术素材

这里保存当前游戏使用的参考项目原图。原图不放入 `web/public`，因此不会被 Vite 或 GitHub Pages 发布，也不需要玩家下载。本目录的文件和清单应随项目一起保存，重新编码不再依赖其他项目目录。

不要用压缩后的图片覆盖这里的原图。裁切、缩放和压缩应由构建脚本完成，发布结果写入 `web/public/assets/`；如需更换美术，请保留原始版本并更新清单的来源信息、散列和尺寸。

`manifest.json` 的每项记录：

- `source`：本目录下的原图相对路径。
- `origin.project`、`origin.path`：最初来源项目及其相对路径，仅供追溯。
- `sha256`：原图字节的 SHA-256 散列，用于发现误覆盖或损坏。
- `width`、`height`：原始及发布尺寸；当前流程保留全部像素和构图，不裁切、不放大。
- `output`：相对于 `web/public` 的发布路径。
- `encoding`：WebP 的质量、编码方法、多线程开关；`format: "copy"` 表示原样复制，避免已有 JPEG 再次有损编码。

当前理念图保留 1024×1024，人物图保留 1408×768，城景保留 1536×1024，以上统一使用 WebP 质量 90、方法 6。两张科技 JPEG 原图为 640×426，直接复制原始字节。

从仓库根目录进入 `web` 后，执行：

```sh
npm run images:build
npm run preload:build
```

重新编码需要安装提供 `cwebp` 的 WebP 工具（macOS 可使用 `brew install webp`）。脚本先校验全部原图，临时生成并校验全部发布图片，再写入发布目录；不会修改原图。普通开发、生产构建和 Pages 部署直接使用已生成的图片，不需要安装编码工具。

仅校验原图散列、发布图片尺寸及原样复制图片的字节是否一致，无需编码工具：

```sh
npm run images:build -- --check
```

新增或替换图片后，还需要更新对应游戏定义或界面的图片路径。脚本不会删除清单以外的文件；确认已无引用后再删除过时发布副本，最后重建预加载清单。
